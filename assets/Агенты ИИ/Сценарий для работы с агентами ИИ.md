# Агент-Отладчик V3 Промт.md

Руководство по передаче задания агенту «Хирургический Отладчик Svelte 5» (Zero-Hallucination Debugger)
Ниже представлен чёткий протокол взаимодействия, который минимизирует риски, исключит галлюцинации и сохранит контроль над качеством.

Перед началом работы убедиться, что все файлы существуют и код компилируется.

Каждый шаг выполнять в отдельной ветке/коммите.

После каждого шага прогонять контрольные точки, фиксируя результат.

При возникновении ошибки в шаге — сообщить и предложить исправление в рамках того же шага.

Не добавлять функционал, не описанный в протоколе.

3. Что делать, если код Отладчика приводит к ошибкам или ломает существующий код
У вас есть безопасная стратегия:

3.1. До начала работ — создайте резервную ветку в Git
bash
git checkout -b feature/complex-fractions
git commit -am "Backup before surgeon"
3.2. На каждый шаг — временный коммит
После получения кода от Отладчика, примените его, проверьте тест. Если всё работает:

bash
git commit -am "Step 1: add marker helpers"
Если не работает — откатите:

bash
git reset --hard HEAD
и сообщите Отладчику:

«Шаг 1 не прошёл тест: [причина]. Вот результат консоли: ... Пожалуйста, исправь, не меняя другие шаги.»

3.3. Если ошибка не в коде Отладчика, а в вашем понимании
Уточните вопрос, переформулируйте шаг.

При необходимости скорректируйте контрольную точку.

3.4. Если Отладчик начал галлюцинировать (предлагает несуществующие функции или меняет архитектуру)
Немедленно остановите сессию и вернитесь к протоколу. Сообщите:

«Ты отклонился от протокола. Давай вернёмся к шагу N. Следуй точно инструкции, не добавляй новый функционал.»

4. Как правильно делать дальнейшие действия после получения каждого шага
Пошаговый алгоритм для вас (человека):

Принять код от Отладчика.

Вставить изменения в соответствующий файл. (Используйте дифф-инструмент или замените функцию целиком, если Отладчик дал полную функцию.)

Запустить ручные тесты из контрольной точки (описаны в шаге).

Если тест пройден:

Закоммитить.

Ответить Отладчику: «Шаг N принят. Переходим к шагу N+1. Вот текст следующего шага.»

Если тест провалился:

Записать фактический результат и ожидаемый.

Ответить Отладчику: «Тест не пройден. Факт: …, Ожидание: …. Исправь, пожалуйста, в рамках этого же шага.»

Не переходить к следующему шагу, пока текущий не будет зелёным.

После завершения всех шагов — провести полное регрессионное тестирование (все примеры из ТЗ, включая преобразования decimalToFraction/fractionToDecimal).

5. Дополнительные советы для безопасной работы с Отладчиком
Не давайте Отладчику доступ к вашему окружению. Он работает только с кодом и текстовыми описаниями.

Не просите его «оптимизировать» или «рефакторить» — только строгое выполнение шагов.

Фиксируйте в диалоге номер текущего шага. Например, пишите: «Текущий шаг: 10 из 25».

Если Отладчик запрашивает больше контекста (например, содержимое другого файла), предоставьте ровно те строки, которые относятся к делу. Не выгружайте весь проект.

После каждого успешного шага делайте копию рабочей директории (или коммит). Это позволит откатиться до любой промежуточной точки.

8. Заключительная рекомендация
Не торопитесь. Даже если Отладчик работает быстро, каждый шаг требует вашего внимания.
Лучше потратить день на пошаговое выполнение 25 шагов, чем потом три дня откатывать сломанный проект.

Правило: Один шаг за один коммит. Один коммит за один ответ Отладчика.

Следуя этому протоколу, вы получите чистый, рабочий код без галлюцинаций и с полной сохранностью существующей логики.
