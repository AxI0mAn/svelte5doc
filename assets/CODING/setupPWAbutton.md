Реализация и тестирование кнопки «Установить» в PWA. 
Это не просто кнопка, как обычная ссылка на скачивание. Браузер сам решает, когда приложение «достойно» установки, но он предоставляет нам событие, которое мы можем перехватить.

Вот пошаговый алгоритм, как это сделать:

1. Как это работает (Теория)
Браузер генерирует событие be14 птforeinstallprompt. Нам нужно:

Перехватить это событие и сохранить его в переменную.

Показать пользователю вашу кастомную кнопку «Установить» (по умолчанию она должна быть скрыта).

При нажатии на кнопку вызвать метод .prompt() из сохраненного события.

2. Реализация кода
Вам нужно создать логику, которая будет слушать браузер. Ниже пример реализации, который можно вынести в отдельный файл или использовать внутри компонента.

3. Обязательные условия (Checklist)
Кнопка не появится, если PWA не соответствует критериям Google:

Manifest.json: Должен быть корректно заполнен (иконки, имя, start_url, display: standalone).

Service Worker: Должен быть зарегистрирован и работать (хотя бы с пустым обработчиком fetch).

HTTPS: Сайт должен работать по защищенному протоколу (исключение — localhost).

Повторная установка: Если приложение уже установлено, событие beforeinstallprompt не сработает.

4. Нюансы для разных платформ
Android (Chrome): Работает идеально по схеме выше.

iOS (Safari): Плохие новости. Safari не поддерживает событие beforeinstallprompt. Пользователи iPhone могут установить PWA только вручную через кнопку «Поделиться» (Share) -> «На экран "Домой"» (Add to Home Screen).

Совет: Для iOS обычно показывают текстовую подсказку с картинкой (инструкцию), как именно нажать кнопку «Поделиться».

Desktop (Chrome/Edge): Работает так же, как на Android. В адресной строке также появится иконка установки.

Как сделать код правильно (в стиле Svelte 5)

1. Файл логики (beforeInstall.js или твои утилиты)
Нам нужно просто хранить deferredPrompt и предоставить функцию-экшен.
JavaScript
import { appStore } from "$lib/store/appStore.svelte";
import { getCurrentISODate } from "./getCurrentISODate";

let deferredPrompt; 

/**
 * Инициализация проверки возможности установки.
 * Запускается один раз при загрузке (в $effect)
 */
export function initPwaLogic() {
  if (typeof window === 'undefined') return;

  window.addEventListener('beforeinstallprompt', (e) => {
    e.preventDefault();
    deferredPrompt = e;

// Если браузер предложил установку, значит приложение точно не установлено 
// Сбрасываем флаг installed, если он вдруг был true 
if (appStore.installed) { appStore.installed = false; }

    // Разрешаем показ кнопки в интерфейсе
    appStore.canInstall = true; 
  });

  window.addEventListener('appinstalled', () => {
    console.log('PWA успешно установлено!');
    deferredPrompt = null;
    appStore.canInstall = false;
    appStore.installed = getCurrentISODate();
  });
}

/**
 * Вызывается при клике на твою кнопку "Установить"
 */
export async function installPwaAction() {
  if (!deferredPrompt) return;

  // Показываем системное окно
  deferredPrompt.prompt();

  // Ждем ответа пользователя
  const { outcome } = await deferredPrompt.userChoice;
  
  if (outcome === 'accepted') {
    console.log('Пользователь принял установку');
  } else {
    console.log('Пользователь отклонил установку');
  }

  // Очищаем, так как событие одноразовое
  deferredPrompt = null;
  appStore.canInstall = false;
}

Почему кнопка появилась только через несколько минут?
У браузеров (особенно Chrome) есть свои внутренние критерии «достойности» (heuristics):
    • Взаимодействие: Юзер должен провести на сайте какое-то время или совершить несколько кликов.
    • Service Worker: Он должен не просто быть, а успешно активироваться и закэшировать файлы.
    • Защита от спама: Браузер не хочет, чтобы каждый сайт предлагал установку в первую же секунду.
На будущее: В режиме разработки это происходит медленнее. На «живом» сайте после первого посещения обычно хватает 10–30 секунд.

Как проверить, что всё работает до конца?
Теперь, когда кнопка Install App Now! появилась (благодаря appStore.canInstall = true), нажми на неё.
    1. Твоя функция installPwaAction() должна вызвать deferredPrompt.prompt().
    2. На экране должно появиться системное окно подтверждения (уже от самого Chrome или твоего браузера).
Важные советы по отладке в DevTools:
Если ты хочешь протестировать это быстрее, не дожидаясь милости браузера:
    1. Открой DevTools (F12).
    2. Перейди на вкладку Application (Приложение).
    3. Слева выбери Manifest.
    4. Там будет ссылка "Installability". Если есть ошибки (например, иконка не того размера), браузер напишет об этом там.
    5. Там же есть кнопка "Install" — она принудительно вызывает событие beforeinstallprompt для тестов.

2. Почему окно не появляется повторно после «Отмены»?

Это стандартная защита браузеров (особенно Chrome) от назойливости сайтов. Если пользователь нажал «Отмена» в системном окне, браузер считает, что вы его спамите, и временно блокирует повторный вызов события beforeinstallprompt.
Как это работает:
    • Иммунитет: После отказа браузер может не генерировать это событие в течение нескольких часов, дней или пока вы не совершите какое-то значимое действие на сайте (много кликов, перезагрузка, повторный вход).
    • Событие одноразовое: Переменная deferredPrompt становится недействительной сразу после того, как метод .prompt() был вызван один раз.
Как «вернуть» окно для тестов прямо сейчас:
Чтобы не ждать милости от браузера во время разработки, сделай следующее:
    1. Сброс в DevTools:
        ◦ Открой Application -> Storage.
        ◦ Нажми кнопку "Clear site data" (это очистит кэш и Service Worker).
    2. Принудительный вызов:
        ◦ Вкладка Application -> Manifest.
        ◦ Нажми на синюю надпись "Install" (справа вверху или в блоке Installability). Это заставит браузер снова выкинуть событие в твой код.
    3. Хардкорный метод:
        ◦ Просто удали сайт из вкладок, закрой браузер и открой инкогнито-окно. В инкогнито PWA обычно не устанавливаются, но события иногда пробрасываются для тестов.
Итог по логике для пользователя:
В реальной жизни, если юзер нажал «Отмена», твоя кнопка «Установить» исчезнет (так как appStore.canInstall = false). Она появится снова только тогда, когда браузер сам решит, что можно предложить установку еще раз (обычно при следующем визите).

В чем разница?
    1. Меню «Три точки»: Это часть интерфейса самого браузера. У него всегда есть доступ к функции установки, потому что он «владелец» процесса.
    2. Твоя кнопка: Она работает через временный «токен» доступа (объект deferredPrompt), который браузер выдает твоему сайту.

Как только ты вызываешь .prompt(), этот токен сгорает. Неважно, нажал пользователь «Установить» или «Отмена» — событие считается использованным. Браузер забирает у сайта право вызывать системное окно до следующего раза.

Как сделать так, чтобы кнопка работала «аналогично» меню?
Напрямую заставить браузер выкидывать beforeinstallprompt каждую секунду нельзя, но можно улучшить логику:
1. Не прячь кнопку совсем (опционально)
Если ты хочешь, чтобы кнопка была видна всегда (как в меню), ты можешь оставить её в DOM, но если deferredPrompt пуст, при нажатии выводить подсказку:
"Нажмите на 'три точки' в браузере и выберите 'Установить приложение', если системное окно не появилось."
2. Понимание жизненного цикла события
    • Вход на сайт: Браузер присылает событие -> Сохраняем в deferredPrompt -> Кнопка активна.
    • Клик по кнопке: Вызываем .prompt() -> Юзер нажал «Отмена» -> deferredPrompt стал null.
    • Дальнейшие действия: Теперь нужно ждать, пока браузер снова пришлет событие. Обычно это происходит при обновлении страницы или следующем визите, если браузер посчитает, что прошло достаточно времени.

Можно ли "выпросить" событие снова?
Есть один полу-хак. Если пользователь нажал «Отмена», и ты хочешь дать ему возможность передумать через 5 минут:
    1. Перезагрузка страницы (location.reload()) — это самый надежный способ заставить браузер заново прогнать проверки. Если условия соблюдены, событие beforeinstallprompt прилетит снова почти сразу.
    2. Инструкция: Если appStore.installed === false, но deferredPrompt пуст, покажи пользователю маленькую инструкцию со скриншотом, как установить через меню браузера. Это и есть «лучшая практика» для тех случаев, когда API браузера недоступно.
Почему браузер так жесток?
Это сделано для защиты от «агрессивных» сайтов. Представь, если бы сайт вызывал системное окно установки каждые 5 секунд после каждого твоего отказа. Это бы превратилось в ад. Поэтому браузер дает сайту только одну попытку на каждый «сеанс одобрения».
