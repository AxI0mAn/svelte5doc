## Кнопка «Поделиться» для мобильных устройств и десктопов работает на стыке двух разных браузерных технологий: нативного API операционной системы и работы с буфером обмена.

Как это устроено под капотом?
Для мобильных (Android/iOS): Используется Web Share API (navigator.share). Браузер дает команду операционной системе, и та снизу экрана выдвигает родную (нативную) шторку со списком приложений (Telegram, WhatsApp, Viber, СМС). Браузер сам туда ничего не передает — он просто отдает ОС текст и ссылку, а дальше операционка делает все сама.

Для десктопов (ПК без поддержки Share API): Используется Clipboard API (navigator.clipboard.writeText). Так как на ПК нет единой шторки шеринга, браузер программно копирует текущий URL в буфер обмена (память устройства), а интерфейс показывает пользователю текстовую подсказку.

Реализация на Svelte 5: Компонент BtnShare.svelte
Вот переиспользуемый компонент, который учитывает особенности SSR (серверного рендеринга SvelteKit) и автоматически переключает логику в зависимости от устройства.

Svelte
<script>
  // Принимаем кастомные классы и кастомный текст для шеринга
  let { customClass = '', shareTitle = 'Посмотрите эту страницу' } = $props();

  // Локальное состояние для отображения тултипа "Ссылка скопирована"
  let showTooltip = $state(false);
  let timeoutId;

  /**
   * Основной обработчик клика по кнопке
   * @param {MouseEvent} e
   */
  async function handleShare(e) {
    e.preventDefault();

    // Защита: на сервере (SSR) ничего не делаем
    if (typeof window === 'undefined') return;

    const shareData = {
      title: shareTitle,
      url: window.location.href // Берём текущий URL из адресной строки
    };

    // 1. Проверяем, поддерживает ли устройство нативный мобильный шеринг
    if (navigator.share && navigator.canShare?.(shareData)) {
      try {
        await navigator.share(shareData);
      } catch (err) {
        // Если пользователь сам отменил шеринг (закрыл шторку), 
        // ловим ошибку AbortError, чтобы билд и консоль не спамили ошибками
        if (err.name !== 'AbortError') {
          console.error('Ошибка шеринга:', err);
        }
      }
    } else {
      // 2. Фолбек для десктопов: копируем ссылку в буфер обмена
      try {
        await navigator.clipboard.writeText(shareData.url);
        
        // Включаем тултип с сообщением
        showTooltip = true;

        // Сбрасываем старый таймер, если пользователь кликнул несколько раз
        clearTimeout(timeoutId);
        
        // Прячем уведомление через 2.5 секунды
        timeoutId = setTimeout(() => {
          showTooltip = false;
        }, 2500);
      } catch (err) {
        console.error('Не удалось скопировать ссылку:', err);
      }
    }
  }
</script>

Подробное обсуждение критических нюансов
При интеграции этой кнопки в твой проект (особенно с учетом того, что это калькулятор или веб-приложение), нужно держать в голове три важные вещи:

1. Безопасность окружения (HTTPS)
И navigator.share, и navigator.clipboard — это современные API безопасности. Они работают строго в безопасном контексте (Secure Context). Это значит:

На localhost (во время разработки) все будет работать отлично.

На реальном хостинге (например, на GitHub Pages) проект обязательно должен работать по протоколу HTTPS. Если зайти на сайт по обычному HTTP, браузер заблокирует обе функции, и кнопка не отработает.

2. Специфика iOS (Safari)
В отличие от Android, где navigator.share работает железно в любом встроенном браузере (Chromium, WebView Телеграма, Firefox), на iPhone системная шторка через Chrome или Firefox для iOS иногда может вести себя нестабильно из-за ограничений Apple. Но наш код застрахован: если Safari или Chrome на iOS по какой-то причине вернет false на проверку navigator.share, компонент мгновенно отработает по второму сценарию — просто скопирует URL в буфер и покажет подсказку. Пользователь в любом случае не останется у разбитого корыта.

3. Динамические URL (Состояние калькулятора)
Сейчас код берет window.location.href. Это идеальное решение, если твой converter/calculator кодирует состояние вычислений прямо в URL (например, /fraction-calc?input=1/2+3/4). Тогда пользователь, поделившись ссылкой с мобильного, передаст товарищу не просто пустой калькулятор, а страницу с уже готовым результатом вычислений. Если тебе нужно передавать строго «чистый» базовый URL без параметров, можно заменить window.location.href на window.location.origin + window.location.pathname.

## Что отправится.

На Android при отправке через Web Share API (navigator.share) отправится текст и ссылка. Отправить полноценную ссылку, которая сразу выглядит как интерактивная картинка, в коде нельзя — то, как именно ссылка отобразится у получателя, целиком зависит от принимающего приложения (Telegram, WhatsApp, Viber).

Однако есть два способа сделать отправку визуально крутой и добавить картинку.

Вариант 1. Отправка реального файла изображения (Через Web Share API)
Современный Web Share API на Android позволяет делиться настоящими файлами (например, сгенерированным графиком, скриншотом калькулятора или логотипом). Браузер передаст в шторку Android файл, и мессенджеры отправят его как картинку, к которой снизу можно прикрепить текстовое описание со ссылкой.

Для этого в метод navigator.share нужно передать массив файлов files.

Пример реализации с отправкой картинки-логотипа:

JavaScript
async function shareWithImage() {
  try {
    // 1. Скачиваем картинку (или генерируем её через Canvas)
    const response = await fetch('/images/share-banner.png');
    const blob = await response.blob();
    
    // 2. Превращаем её в объект File, который понимает операционная система
    const file = new File([blob], 'share-banner.png', { type: blob.type });

    const shareData = {
      title: 'Мой Конвертер',
      text: 'Посмотри, какие крутые расчеты я сделал!',
      url: window.location.href,
      files: [file] // <-- Передаем файл картинки в Android
    };

    // Проверяем, может ли устройство расшарить именно файлы
    if (navigator.canShare && navigator.canShare(shareData)) {
      await navigator.share(shareData);
    }
  } catch (err) {
    console.error('Не удалось поделиться с картинкой:', err);
  }
}
Как это выглядит на Android: В шторке шеринга сверху появится превью твоей картинки, а когда пользователь выберет, например, Telegram, в чат отправится изображение, под которым в качестве подписи (caption) будет идти твой текст и ссылка.

Вариант 2. Красивое превью ссылки (Open Graph теги) — Самый частый подход
Если ты хочешь, чтобы пользователь отправлял просто ссылку, но в чате у получателя она автоматически превращалась в красивую карточку с картинкой, заголовком и описанием — файлы в коде передавать не нужно.

За это отвечают Open Graph (meta) теги в вашем +page.svelte или app.html. Принимающее приложение (Telegram, VK, Viber) само переходит по отправленной ссылке, парсит эти теги и рисует красивый блок.

Чтобы это работало, на странице должны быть прописаны мета-теги:

HTML
<svelte:head>
  <title>Универсальный калькулятор дробей</title>
  <meta property="og:title" content="Универсальный калькулятор дробей" />
  <meta property="og:description" content="Считайте дроби и переводите исторические меры длины в один клик с разбором шагов." />
  <meta property="og:url" content="https://твой-сайт.ru/context" />
  <!-- Ссылка на картинку, которая отобразится в мессенджере -->
  <meta property="og:image" content="https://твой-сайт.ru/images/preview-banner.jpg" />
  <meta property="og:type" content="website" />
</svelte:head>
Резюме: что выбрать?
Если нужно отправить динамический результат (например, пользователь хочет поделиться именно графиком или скриншотом своих вычислений, созданным через HTML5 Canvas прямо сейчас) — используй Вариант 1 (передачу массива files).

Если нужно, чтобы при отправке ссылки на калькулятор/конвертер просто подтягивался красивый фирменный баннер приложения — используй Вариант 2 (Open Graph теги).

## Чтоб отправилось превью



Чтобы принимающий пользователь увидел не просто «голую» ссылку, а красивое визуальное превью с картинкой, тебе нужно использовать Open Graph (OG) теги.

Когда человек делится ссылкой в Telegram, WhatsApp или VK, мессенджер считывает эти скрытые теги с твоего сайта и сам превращает ссылку в аккуратную карточку.

Вот как это работает и как правильно настроить в SvelteKit:

Шаг 1. Добавляем мета-теги на страницу
В SvelteKit для этого используется специальный встроенный компонент <svelte:head>. Вставь этот блок в самый верх своего файла страницы +page.svelte (или в главный +layout.svelte, если превью должно быть одинаковым для всего сайта):

Svelte
<svelte:head>
  <!-- Заголовок карточки в мессенджере -->
  <meta property="og:title" content="Калькулятор дробей и мер длины" />
  
  <!-- Краткое описание под заголовком -->
  <meta property="og:description" content="Универсальный инструмент для точных расчетов с разбором шагов вычислений." />
  
  <!-- ПРЯМАЯ ССЫЛКА НА КАРТИНКУ БАННЕРА -->
  <meta property="og:image" content="https://antopaz.ru/images/share-preview.png" />
  
  <!-- Размеры картинки, чтобы мессенджер сразу выделил под неё правильное место -->
  <meta property="og:image:width" content="1200" />
  <meta property="og:image:height" content="630" />
  
  <meta property="og:type" content="website" />
</svelte:head>

Шаг 2. Нюансы Web Share API на Android
Когда твоя кнопка «Поделиться» вызывает нативный шеринг на Android, тебе достаточно передать туда обычный URL (мессенджеры сами спарсят теги, которые мы прописали на Шаге 1).

Но чтобы Android-шторка при отправке сразу показывала красивую иконку сайта, добавь свойство text в объект shareData:

JavaScript
const shareData = {
  title: 'Проект Antopaz',
  text: 'Посмотри этот крутой калькулятор!', // Мессенджеры используют это как текст сообщения
  url: window.location.href // Ссылка, к которой прикрепится картинка из Open Graph
};

await navigator.share(shareData);
⚠️ Три железных правила, чтобы картинка завелась:
Абсолютный URL для og:image: Ссылка на картинку обязательно должна быть полной, начиная с протокола. Вариант /images/preview.png не сработает. Мессенджеры не умеют догадываться, с какого домена брать картинку, поэтому пиши строго: [https://твойдомен.ru/images/preview.png](https://твойдомен.ru/images/preview.png).

Пропорции картинки: Идеальный стандарт для современных мессенджеров — соотношение сторон 1.91 : 1 (рекомендуемый размер 1200 × 630 пикселей). В таком формате баннер в Telegram или WhatsApp будет большим, сочным и во всю ширину сообщения, а не маленьким квадратиком сбоку.

Кэш мессенджеров (Важно при тестировании): Если ты уже один раз отправил ссылку другу, а потом поменял картинку на сайте — в чате всё равно будет отображаться старая картинка. Мессенджеры намертво кэшируют превью.

Как исправить: Для Telegram используй официального бота-освежителя: @WebpageBot. Отправь ему ссылку на свой сайт, и он принудительно обновит картинку и описание в базе данных Telegram.

## <svelte:head> для конкретной страницы

для страниц вроде basic/+page.svelte (или любой другой конкретной страницы) нужно и можно создать свой отдельный <svelte:head>.

В SvelteKit блоки <svelte:head> на разных уровнях вложенности не заменяют друг друга полностью, а сливаются (merge). При этом свойства с одинаковыми именами (например, <title> или одинаковые <meta>) перезаписываются внутренними страницами. То есть настройки из +page.svelte имеют приоритет над глобальными из +layout.svelte.

У тебя есть два отличных пути, как это реализовать, в зависимости от того, динамические там данные или статические.

Вариант 1. Прямо в файле src/routes/(math)/basic/+page.svelte (Простой путь)
Если для страницы базового калькулятора нужны фиксированные тексты и картинка, ты просто прописываешь <svelte:head> прямо внутри этого файла.

Svelte

<!-- src/routes/(math)/basic/+page.svelte -->
<script>
  // Твой логический код страницы
</script>

<svelte:head>
          <!-- Этот title перебьет глобальный "caloca" из +layout.svelte -->
        <title>Базовый калькулятор | caloca</title>
      
          <!-- Уникальное превью для этой конкретной страницы -->
         <meta property="og:title" content="Базовый онлайн-калькулятор" />
          <meta property="og:description" content="Простые арифметические вычисления, проценты и корни с выводом шагов решения." />

      <meta property="og:image:width" content="1200" />
      <meta property="og:image:height" content="630" />
     <meta property="og:image:type" content="image/png" />

          <meta property="og:image" content="https://antopaz.ru/images/preview-basic.png" />
          <meta property="og:url" content="https://antopaz.ru/basic" />
</svelte:head>

<main>
  <!-- Контент твоей страницы -->
</main>



Что произойдет при отправке ссылки: Когда бот мессенджера перейдет по ссылке /basic, он увидит иконку из главного лейаута, но заголовок, описание и картинку возьмет именно из этого локального <svelte:head>.

Вариант 2. Динамический через промежуточный (math)/+layout.svelte (Архитектурный путь)
Обрати внимание на свою структуру папок: у тебя есть крутая группировка роутов в круглых скобках, например (math).
Если ты хочешь, чтобы у всех математических калькуляторов (basic, engineer, fraction, trigonometry) был похожий стиль превью, но с разными заголовками, ты можешь создать локальный лейаут для этой группы.

Создай файл src/routes/(math)/+layout.svelte (если его еще нет).

Напиши там один динамический <svelte:head>, который будет принимать данные через пропсы или состояние:

Svelte
<!-- src/routes/(math)/+layout.svelte -->
<script>
  let { children } = $props();
</script>

<!-- Этот лейаут автоматически применится ко ВСЕМ страницам внутри папки (math) -->
{@render children()}
Однако, учитывая твой аскетичный стиль и то, что страниц не так много, Вариант 1 (прописать индивидуальный блок прямо в конкретный +page.svelte) — самый надежный, явный и изолированный. Ты сразу видишь, какая картинка и какой текст уходят в шеринг при отправке именно этой страницы.

## Требования для превью и текстов

 

Вот четкие технические стандарты для og:image, чтобы картинка гарантированно отображалась в мессенджерах и соцсетях, а не превращалась в обрезанный или размытый квадрат.

1. Требования к размеру (Разрешение и пропорции)
Идеальный стандарт: 1200 × 630 пикселей.
Это золотой стандарт для Telegram, WhatsApp, Viber и VK. При таком размере ссылка превращается в большую, сочную горизонтальную карточку во всю ширину сообщения.

Соотношение сторон: 1.91 : 1 (горизонтальное).

Минимальный размер для большой карточки: 600 × 315 пикселей. Если загрузить картинку меньше (например, 400 × 200), мессенджеры сожмут её и покажут как маленькое квадратное превью сбоку от текста, а не как полноценный баннер.

Максимальный вес файла: До 5 МБ (но лучше оптимизировать её и сжать до 200–500 КБ, чтобы боты мессенджеров скачивали её мгновенно).

2. Требования к типу файла (Формат)
Поддерживаются три основных формата:

PNG — Лучший выбор для интерфейсов, скриншотов и калькуляторов. Графика, текст и мелкие детали (например, формулы или иконки) останутся четкими и не размоются.

JPEG / JPG — Отлично подходит, если на превью используется реальная фотография или сложный градиент с кучей цветов.

WEBP — Современный формат с отличным сжатием. Большинство современных мессенджеров (Telegram, WhatsApp) его уже прекрасно понимают, но для 100% обратной совместимости со старыми сервисами безопаснее использовать PNG или JPG.

⚠️ Важно: Векторный формат SVG использовать нельзя. Боты мессенджеров не умеют рендерить вектор на лету, поэтому ссылка с SVG-картинкой просто останется без изображения.

3. Главные правила безопасной верстки баннера
Когда будешь рисовать или генерировать превью для страниц проекта:

Контентная безопасная зона: Мессенджеры могут слегка скруглять углы карточки или немного подрезать края на разных смартфонах. Держи все важные элементы (логотип, название страницы, текст) ближе к центру, отступая от краев баннера минимум по 50–60 пикселей.

Абсолютный путь: Браузеру внутри сайта можно скормить относительный путь /images/share.png, но для og:image путь в теге обязательно должен быть полным: [https://site.ru/images/share.png](https://site.ru/images/share.png).

Указание размеров в коде: Всегда добавляй сопутствующие теги ширины и высоты. Это помогает мессенджерам мгновенно зарезервировать правильный прямоугольник под картинку ещё до того, как они полностью её скачают:

HTML
<meta property="og:image" content="https://antopaz.ru/images/preview-math.png" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta property="og:image:type" content="image/png" />
