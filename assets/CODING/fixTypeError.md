1. Как убрать ложные ошибки в Svelte 5 (JS)
То, что вы видите, — это не ошибки в вашем коде, а работа LSP (Language Server Protocol), который после обновления переключился в режим строгой проверки типов (будто вы пишете на TypeScript).

линтер (проверка синтаксиса) не отключится полностью, но его поведение кардинально изменится.

Вот что именно произойдет, если вы добавите jsconfig.json с параметром "checkJs": false:

1. Отключится "Тайп-чекинг" (Проверка типов)
Это именно то, что вам сейчас нужно. VSCodium перестанет пытаться угадать типы ваших переменных и не будет подсвечивать красным строки, где, по его мнению, «число не может быть строкой» или «объект не соответствует интерфейсу». Те самые ошибки типизации, которые появились после обновления, исчезнут.

2. Сохранится проверка синтаксиса
Если вы совершите реальную ошибку в JavaScript (например, забудете закрыть скобку или допустите опечатку в ключевом слове function), VSCodium всё равно подсветит это. Линтер продолжит следить за тем, чтобы код был валидным с точки зрения правил JS.

3. Улучшится навигация в проекте
Сам по себе файл jsconfig.json говорит редактору: «Все файлы в этой папке — часть одного проекта». Это позволит VSCodium:

Лучше понимать связи между вашими файлами в Svelte 5.

Корректно работать автодополнению (IntelliSense) при импортах.

Быстрее переходить к определениям функций (через Ctrl + Click).

Для вашего проекта на Svelte 5 использование jsconfig.json — это лучший способ «укротить» редактор, не теряя при этом полезных функций вроде автодополнения кода.

Вот рекомендуемый код с подробными комментариями. Вы можете просто скопировать его целиком и создать файл в корневой папке проекта.

JSON
{
  "compilerOptions": {
    /* 1. Основа проекта */
    "module": "esnext",       // Позволяет использовать современные импорты (import/export)
    "target": "esnext",       // Указывает, что код пишется под самые современные стандарты JavaScript
    
    /* 2. Отключение лишних проверок (Ваш случай) */
    "checkJs": false,         // ОТКЛЮЧАЕТ проверку типов в .js файлах. Красные подчеркивания исчезнут!
    "checkSvelte": false,     // Отключает строгую проверку типов внутри Svelte-компонентов
    
    /* 3. Улучшение работы редактора */
    "allowJs": true,          // Разрешает редактору обрабатывать JavaScript файлы (базовая опция)
    "resolveJsonModule": true, // Позволяет импортировать данные напрямую из .json файлов (удобно для i18n)
    "moduleResolution": "node", // Говорит редактору искать библиотеки в папке node_modules, как это делает Node.js
    
    /* 4. Пути (Aliases) */
    "baseUrl": ".",           // Точка отсчета для путей — корень вашего проекта
    "paths": {
      "$lib/*": ["src/lib/*"] // Настройка для SvelteKit, чтобы путь $lib/ работал корректно в редакторе
    }
  },
  
  /* 5. Исключения (Что НЕ нужно сканировать) */
  "exclude": [
    "node_modules",           // Огромная папка с библиотеками, её проверка только тормозит iMac
    "dist",                   // Папка с готовой сборкой проекта
    ".svelte-kit"             // Служебная папка SvelteKit (редактор сам разберется с ней позже)
  ]
}
Почему это сработает для вас?
"checkJs": false: Это главный «выключатель» тех самых раздражающих красных линий. Линтер перестанет считать, что вы обязаны описывать типы каждой переменной.

Производительность: Исключение папки node_modules из сканирования сэкономит ресурсы вашего процессора и 8 ГБ ОЗУ, так как VSCodium перестанет постоянно «переваривать» тысячи файлов библиотек в фоновом режиме.

Сохранение интеллекта: Редактор всё равно будет подсказывать вам названия функций и методов из ваших файлов, так как он понимает структуру проекта через этот конфиг.
